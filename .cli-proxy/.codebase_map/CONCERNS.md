## Известные проблемы (техдолг)
- **Контроль доступа в callback-обработчиках сессий** — закрыт. `SessionManager.get_by_uid` резолвит сессию по глобальному индексу всех чатов, а uid приходит из подделываемой `callback_data`, поэтому все обработчики, резолвящие сессию из payload, проходят через общий хелпер `SessionActionsMixin._ensure_session_visible` (`tg/callback_actions/session.py:119`): он сверяет `handlers._is_session_visible_for_chat` по чату РЕАЛЬНОГО запроса (из `_callback_scope`) и fail-closed при сбое проверки. Покрыты `_cb_sess_active_pick`, `_cb_user_project_menu`, `_handle_user_project_pick`, `_cb_sess_cli`, `_cb_sess_backend`, `_cb_sess_transfer_yes`, `_cb_sess_transfer_no`, `_cb_sess_mode_pick`, `_cb_sess_ssh_toggle`, `_cb_sess_snapshot`, `_cb_sess_unread_toggle`, а также `_cb_orch_transition` (`tg/callbacks.py:242`) — там был тот же дефект вне этого файла. `_cb_sess_tmux_reread` сознательно без проверки видимости: кнопка admin-only, и `_is_admin` по владельцу запроса (`owner_chat_id` из `_callback_scope`, `tg/callback_actions/session.py:816`) строже. Брать там `chat_id` нельзя: в group-режиме это id общей супергруппы, а не пользователя (тесты `tests/test_tg_handlers.py::test_tmux_reread_callback_checks_admin_by_owner_not_reply_chat` и `::test_tmux_reread_callback_denies_ordinary_member_of_admin_group`). Тесты: `tests/test_session_callback_access_control.py` (подделка callback_data для каждого обработчика плюс позитивные кейсы админа/владельца).
- **Контроль доступа в mode-callback-роутере** — закрыт. `ModeCallbackRouterService._resolve_explicit_session` (`modes/sdk/services/mode_callbacks.py:181`) резолвила `s=<uid>` из payload через глобальный `get_by_uid`, из-за чего `ma:agent:clean_session` / `clean_all` (`modes/agent/mode.py`) удаляли файлы чужой сессии. Теперь глобальные ветки резолва проходят `_is_explicit_session_access_allowed` (админ → `is_session_allowed_for_chat` → совпадение `chat_id`), а `handle_mode_action_callback` при отказе прерывает обработку с `msg.error.session_unavailable`, а не подставляет собственную сессию вызывающего. Chat-scoped ветка (короткий `session_id`) проверки не требует. Права при этом сверяются с ВЛАДЕЛЬЦЕМ запроса: `tg/callbacks.py::_handle_mode_action_callback` резолвит его через `_callback_scope` и передаёт `owner_chat_id=` в роутер, а `handle_mode_action_callback` сводит его в `access_chat_id` (`modes/sdk/services/mode_callbacks.py:399`) для ownership-гейта, `is_mode_allowed_for_chat` и `authorize_mode_launch`. Брать там `chat_id` нельзя: это чат сообщения, и в group-режиме проверка по нему и отказывала владельцу сессии, и — если id супергруппы попал в `admlist_chat_ids` — выдавала админские права любому её участнику. Тот же `access_chat_id` идёт в run-гейт shared-операций `doctor`/`recover`/`resume`/`apply_recommendation` (`policy.is_admin` и `user_id` для `RunOperationsPolicy.can_run_operation`, `modes/sdk/services/mode_callbacks.py:539`, `:549`) и в `promote_run_skills` (`:635`): там `chat_id` был опаснее вдвойне, потому что `RunOperationsPolicy._session_owner_tokens` принимает и `conversation_scope.chat_id`, то есть id самой группы засчитывался как владелец сессии. Тесты: `tests/test_mode_callback_access_control.py` (`test_clean_session_allows_owner_from_group_topic`, `test_clean_session_denies_group_member_when_group_id_is_in_admlist`, `test_clean_session_denies_when_ownership_check_raises`, `test_recover_denies_group_member_when_group_id_is_in_admlist`, `test_recover_allows_admin_from_group_topic`).
- **Контроль доступа внутри agent-режима и в отрисовке меню** — закрыт. Роутер кладёт владельца запроса в `ctx["access_chat_id"]` (`modes/sdk/services/mode_callbacks.py:702`), а `AgentMode.handle_callback` разводит его с `chat_id` и передаёт в `_cb_project_connect`, `_cb_project_pick` и `_set_project_root` (`modes/agent/mode.py`): там `bot_app.is_admin`/`user_projects` брали чат сообщения, из-за чего участник группы с id группы в `admlist_chat_ids` получал админский file-picker по всему дереву вместо своих `user_workdirs`. Через dirs-flow тот же `_set_project_root` вызывается уже с владельцем (`tg/callback_actions/dirs.py:79`, `:221`). `build_mode_menu_visibility` (`app/services/menu_visibility_policy.py:186`) по той же причине считала `is_admin` по `session.chat_id`, игнорируя переданный `user_id`; теперь оба права идут по `actor_id`, а `BaseMode._rerender_menu_common` (`modes/sdk/base.py:587`) передаёт `user_id` наравне с двумя другими вызывающими. Тесты: `tests/test_mode_callback_access_control.py::test_project_connect_denies_admin_file_picker_to_group_member`, `::test_project_connect_allows_admin_file_picker_from_group_topic`, `tests/test_menu_visibility_policy.py::test_mode_menu_admin_flag_follows_actor_not_session_chat`.
